How to Use

  • Open `preview.html` first as the hub for test pages.
  • Use `preview_index.html` to check interaction-heavy flows before flashing the device.
  • Use `preview_wifi.html` to validate settings UX and state persistence.
  • Use `preview_info.html` to verify diagnostics layout and localization.

What to Verify

  • Normal state: battery healthy, one or more feed times, active controls.
  • Edge state: empty schedule, blocked manual feed, low battery, sleep countdown.
  • AP/setup state: WiFi settings, reconnect copy, display/power-save controls.
  • Localization: `localStorage.setItem('aqua_lang', 'uk')` or `'en'` and reload.

Developer Notes

  • These pages are intentionally device-free and rely on mocked values.
  • They should stay available even if the firmware API changes internally.
  • When UI changes, update the preview pages in the same task so the test harness stays useful.

Suggested workflow: preview pages first, backend/frontend integration second, real ESP32 validation last.
